# PharmaLIMS 2026.10.19.309 — تصحيحات المصدر


## تصحيح v309
- إصلاح مسار إعادة المصادقة لتوقيع Review/Approve لنشاطات الأجهزة داخل Trusted Signing Host.
- إضافة `20261030_001_Trusted_Activity_Authentication_Bridge.sql` بدل وصول الخدمة المباشر إلى أعمدة كلمات المرور.
- لا حاجة لإعادة إنشاء Activity 10؛ يستمر من حالة Submitted بعد تطبيق الترحيل وتحديث الخدمة.
- يبقى EQ001 primary database كما هو، ويستمر Activity Signing على قاعدة UAT المحددة فقط.

هذه حزمة مصدر مرشحة لإصلاح ملاحظات F01–F07 بتاريخ 17 أكتوبر. تُطبّق على المشروع الحالي نفسه؛ لا تتضمن برنامج EXE مبنيًا أو قاعدة بيانات، ولا تنفذ تحويل صلاحيات SQL.

## ما تغير
- حماية أصل التوقيع في SQL، وحماية محتوى سجل الأجهزة المعتمد وروابطه، وفحص البصمة قبل الطباعة.
- قراءة مؤشر جاهزية حساب الموقّع دون كشف password hash أو salt.
- استكمال فحوص المياه المعلقة أثناء/بعد التحقيق دون تعديل النتائج المكتملة، ورفض توقيع بيانات غير محفوظة أو نسخة قديمة.
- إظهار المدى الكامل للكلور وpH من المواصفة المحفوظة.
- تحديث هوية المرشح وبصمات المصدر؛ حفظ بيانات الإصدار السابق في docs/release-history.

## التحقق المحلي
اجتازت فحوص المصدر Python والتحقق البنيوي. لم يُنفذ بناء .NET أو تشغيل Windows/WPF/SQL في بيئة إعداد هذه الحزمة. عدم توفر سجل Git يؤدي إلى تخطي اختبار مقارنة تاريخية واحد فقط، مع إبقاء المقارنة فعالة عند توفر الالتزام الأصلي.

## التحقق على Windows
أغلق PharmaLIMS قبل بناء مخرجات تشغيله. من مجلد PharmaLIMS شغّل:

```powershell
$env:PHARMALIMS_TEST_MASTER_CONNECTION_STRING='Server=.\SQLEXPRESS;Integrated Security=True;Encrypt=True;TrustServerCertificate=True;'
Remove-Item Env:PHARMALIMS_CREATE_CLEAN_UAT -ErrorAction SilentlyContinue
.\scripts\Invoke-ReleaseValidation.ps1 -RunDatabaseIntegration -RunRuntimeSmoke
```

الاختبارات تنشئ قواعد مؤقتة معزولة؛ راجع السجل كاملًا. لا تشير هذه الخطوة إلى نجاح Windows إلا بعد تنفيذها فعلًا. لا تطبق ترحيلات على قاعدة التشغيل اعتمادًا على نجاح فحوص Python وحدها.

## EQ-001 وترتيب UAT
1. طبّق الترحيل الإضافي الجديد بالمسار المتحكم المعتمد على قاعدة UAT معزولة أولًا؛ لا تعدّل الترحيلات التاريخية ولا سجلات الاعتماد القديمة.
2. جهّز هوية الخدمة المخصصة بسكربت provisioning المحدّث وصلاحياته المحدودة.
3. قبل التحويل النهائي، يمكن لمسؤول UAT تشغيل الخدمة في وضع Rehearsal المعزول عبر tests/eq001_run_signing_host_uat.ps1 -Rehearsal. هذا لا يغيّر أذونات EXECUTE؛ SQL يفرض أصل الخدمة الموثوق وحماية المحتوى في كل طلب.
4. اختبر مراجعة واعتمادًا صحيحين بحسابين مؤهلين، ورفض الدور المشترك والتوقيع المزور والتعديل على المعتمد والنسخ القديمة. اختبر سير المياه والتقارير كذلك. لا تُعد self-test أو اختبارات SQL الاصطناعية دليل قبول Windows وظيفي.
5. بعد النجاح الفعلي وتوثيق مرجع الدليل، يسجل المسؤول قبول UAT بالسكربت tests/eq001_record_uat_acceptance.sql. قيمه الافتراضية ترفض التسجيل حتى تُستكمل الأدلة والنتائج.
6. بعدها فقط نفّذ tests/eq001_permission_cutover_after_uat.sql في UAT المعتمد، ثم اختبر الخدمة في الوضع العادي دون Rehearsal وأعد اختبارات الرفض. نشر الإنتاج يحتاج إجراء الإصدار المعتمد؛ خدمة هذه الحزمة تظل مقيدة بأسماء UAT المعزولة.

لا تتضمن هذه الحزمة تغيير كلمات مرور أو تجاوز MustChangePassword أو حذف عينات أو إعادة حساب/كتابة النتائج التاريخية. النسخة ليست Freeze/Release حتى تنجح اختبارات Windows وSQL وUAT وتُقبل أدلتها.
