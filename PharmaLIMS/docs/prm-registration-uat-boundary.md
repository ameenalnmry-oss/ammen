# Restricted PRM registration in EQ001 UAT

The AMEEN sample Save handler now routes new registrations through the trusted host whenever trusted signing is enabled. The host has an independent `EnablePrmRegistrationUat` switch, disabled by default. An unavailable or disabled host returns an error; the client does not fall back to direct writes. Existing sample editing and AMEEN specification controls remain in their existing paths.

`PrmRegistrationRequest` preserves the current form fields while excluding sample ID/number, actor, lifecycle status and specification version authority. The authenticated host ticket supplies the actor; SQL independently checks the active account's registration permission and authentication rowversion. The exact target is `tcp:AMEEN,1433` / `EQ001_UAT_AMEEN_20261024`, with validated encrypted transport. The host requires Windows integrated authentication; the desktop target guard also permits the protected restricted SQL authentication test configuration.

`dbo.EQ001_UAT_PrmRegistration` runs as owner and accepts only the existing independent Windows signing principal. Within the host's serializable transaction, it checks the current hash-pinned supersession controls, resolves the current active/effective scoped specification with attributable review and approval signatures, locks numbering, inserts the sample, copies controlled tests including timing/version/source references, writes AuditTrail and appends an immutable outcome receipt. The existing PRM registration workflow has no separate electronic-signature write, so none is added. Fresh trusted authentication and original reason/meaning are retained. Numbers above 9999 retain all digits; missing or ambiguous sequence configuration and exhausted integer capacity fail closed.

For a new request, the existing form validation runs before capture, including conversion of the after-packaging production stage to Finished Product. The pure form mapper marks DatePicker calendar and sampling values as unspecified laboratory wall-clock values without changing their ticks or calendar dates; strict host parsing continues to reject client timezone authority. Recovery uses the original saved payload without validating an unrelated current form.

Before first dispatch, the desktop flushes a DPAPI-protected private recovery record. An uncertain response retains the original request identity, payload, target, actor, Windows SID, reason and meaning. Recover/retry returns the original outcome. Cancel appends a tombstone unless the request already committed, in which case the original saved sample is returned. After a committed outcome the form is cleared; editing requires selecting the persisted sample in the list, preventing unrelated draft fields from overwriting a recovered record.

## Deployment prerequisites

Use only the isolated named UAT target. Keep both the independent flag and the staging script's local `@VerifiedIsolatedUat` switch disabled until the target and dependencies have been reviewed. Stage `scripts/EQ001_UAT_Prm_Registration.sql` using an authorized UAT schema administrator after explicitly changing its local opt-in in the execution batch. Do not change the repository default. The script refuses unknown existing procedure/receipt-trigger definitions and grants only EXECUTE on this one procedure to `PharmaLIMS_TrustedEquipmentSigner`; it does not grant desktop or service table DML. No existing sample, result, profile, signature or historical audit rows are updated by staging.

Require the existing hash-pinned controlled supersession views and append-only trigger, actual PRM schema (including specification/timing snapshot columns), and a single configured sequence row for each category being registered. Preserve the AMEEN source overlays when installing the shared registration partial and recovery class. Deploy the host and trusted assembly built from the same source, including the independent endpoint flag/actions. Do not enable Production support or merge PR62 as part of this change.

Native UAT acceptance must still verify Windows service caller mapping, TLS, actual service/desktop SQL grants, AMEEN Admin registration, fresh authentication, lost-response recovery/cancellation/restart, category-specific UI entry and the deployed site's triggers/constraints. This implementation does not claim those native checks were executed in Linux.

## Local evidence

Portable `PharmaLIMS.PrmRegistrationRegression` exercises typed round trips/hash stability, forbidden actor properties, duplicate JSON fields, required category scopes, exact quantity/date precision, and strict target/TLS/host-authentication guards. `test_prm_registration_boundary.py` checks new-save routing and recovered-form isolation.

`PharmaLIMS.PrmRegistrationSqlRegression` uses disposable SQL Server databases and separate restricted service/desktop SQL logins with certificate validation enabled. Its fixture derives PRM table contracts from repository migrations, reuses supplied site Users/AuditTrail contracts, and installs the original supersession view/trigger definitions so integrity checks remain active. Only the ephemeral batch's target literals and Windows principal type are adapted for this test. The tests exercise direct DML/procedure denials, atomic snapshots and audit, identical and changed request replay, SID/permission/rowversion enforcement, pending cancellation, rollback, concurrent requests, sequence rollover/capacity, missing approval evidence and append-only receipts. They remove all generated databases and logins in `finally`.
