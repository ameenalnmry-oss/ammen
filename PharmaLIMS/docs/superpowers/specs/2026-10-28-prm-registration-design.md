# PRM registration restricted UAT boundary

The actual AMEEN Save path calls InsertSample then GetNextSampleNumber and fails at UPDATE dbo.PRM_NumberSequences for the restricted desktop. Existing PRM registration already groups numbering, the sample, approved-test snapshots and AuditTrail in one transaction; registration does not require a separate electronic signature. Preserve that workflow and all AMEEN trusted specification controls.

Introduce an independently disabled PrmRegistration endpoint, strict typed request without actor/number/status/version authority, and service-authenticated actor/rowversion/caller SID. A single execute-as-owner procedure restricted to the exact EQ001 UAT database and signing Windows principal locks a request receipt and sequence, revalidates permission and approved effective scoped signature-backed specification, assigns test snapshots, inserts sample/audit/receipt atomically. Resolve returns the immutable result; Cancel records a tombstone. Replays bind request ID to canonical payload, actor and SID. Local DPAPI private durable recovery is persisted before dispatch; an uncertain outcome blocks new IDs. No desktop or service direct DML grants, Production support, historical edits or PR62 merge.

UI preserves existing edit behavior and routes only new registrations to the independent flag. UAT disabled configuration fails closed; it must never silently fall back to direct writes. Test request validation, strict deserialization, target binding, sequence overflow, rollback, replay, cancellation, concurrent requests and permission denial on disposable SQL, then native AMEEN Windows deployment validation.
