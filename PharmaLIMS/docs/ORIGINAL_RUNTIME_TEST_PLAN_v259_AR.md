# خطة تحقق تشغيلية — PharmaLIMS 2026.9.6.259

## الحالة والبيئة

**الحالات الواردة في هذا الملف لم تُنفذ ضمن المراجعة.** نُفذت فحوص المصدر واختبارات Python فقط، كما هو موثق في سجلاتها. الأمثلة التالية بيانات اصطناعية لتثبيت السلوك المطلوب، وليست بيانات مرضى أو نتائج تشغيلية.

استخدم Windows وSDK المطابق للمشروع وقاعدة SQL Server معزولة يمكن حذفها وإعادة إنشائها. لا تنفذ تجارب السباق أو تعديل الصلاحيات أو ترحيلات الاختبار على الإنتاج. ثبّت بيانات بدء واضحة، وسجّل نسخة المصدر والمخطط والتوقيت والحسابات الاختبارية دون حفظ كلمات المرور.

احتفظ بنسخة للبيانات قبل الاختبار. استخدم حسابات منفصلة للمحلل والمراجع والمعتمد والإدارة. في تجارب التزامن، استخدم اتصالين مستقلين وحاجزًا معلوم الموضع أو نقطة توقف في نسخة اختبار، بدل الاعتماد على تكرار النقر عشوائيًا.

## الأوامر الأساسية

من مجلد مشروع PharmaLIMS الأصلي، شغّل:

```powershell
python -B scripts/validate_project.py --delivery-package
python -B -m unittest discover -s tests -p "test_*.py" -v

dotnet restore .\PharmaLIMS.csproj --runtime win-x64
dotnet build .\PharmaLIMS.csproj --configuration Release --runtime win-x64 --no-restore
```

نجاح استعادة الحزم ليس نجاح بناء. احتفظ بناتج البناء الكامل وكود الخروج، وميّز تحذيرات المصدر عن فشل الاعتماديات أو إعداد الموقع.

### اختبارات SQL الأصلية

المشروع الأصلي يتضمن:

`tests/PharmaLIMS.DatabaseIntegration/PharmaLIMS.DatabaseIntegration.csproj`

يتعامل البرنامج مع متغير البيئة `PHARMALIMS_TEST_MASTER_CONNECTION_STRING`، ويستخدم افتراضيًا LocalDB. ينشئ قاعدة باسم `PharmaLIMS_Integration_` مع لاحقة عشوائية، ويطلب حذفها عند نهاية المسار؛ يحتاج الحساب إذن الإنشاء والحذف. هذا وصف للمصدر، وليس ضمانًا لتنظيف قاعدة بعد قتل العملية أو انقطاع الجهاز. تحقّق من القواعد المتبقية على خادم الاختبار.

```powershell
# Execute only on an isolated test server.
# Set PHARMALIMS_TEST_MASTER_CONNECTION_STRING securely when not using LocalDB.
dotnet run --project .\tests\PharmaLIMS.DatabaseIntegration\PharmaLIMS.DatabaseIntegration.csproj --configuration Release
```

لا تمرر اتصال إنتاج لهذا الاختبار. لا تنشر سجلًا يحتوي كلمة مرور أو سلسلة اتصال حساسة.

### اختبارات المقيم الجديدة

من مجلد حزمة المراجعة:

```powershell
$src = (Resolve-Path "C:\Path\To\Original\PharmaLIMS").Path
dotnet run --project .\probes\PrmEvaluatorProbes.csproj --configuration Release "-p:PharmaLimsRoot=$src"
```

يربط المشروع ملفي المقيم من المصدر المحدد أثناء البناء، ولا يعدلهما. يحتوي 24 حالة، ويعيد كود خروج 1 عند إخفاق أو استثناء، و0 إذا نجحت كلها. لا تُحوّل توقعات الحالات إلى المخرجات الخاطئة بهدف جعل الاختبار أخضر.

الصيغ غير المدعومة في حالات F05 متوقع أن ترجع `Check Required` وفق عقد الاختبار المرفق. اعتماد دعم لغوي جديد لها يتطلب تعريفًا مستقلًا للقواعد وتعديل الاختبار بمراجعة، لا قبول أجزاء من العبارة.

## حالات الإغلاق الأساسية

### RT-01 — مصدر حجم الهواء وحساب النتيجة — F01

أنشئ حدث Active Air Sampling بدليل أصلي: حجم 1000 لتر وحد إجراء 50. أدخل عدًّا مقداره 60. تحقق من 60 CFU/m³ وحالة OOS. اختبر أن حجم الهواء غير قابل للتعديل في الشاشة، ثم اختبر طبقة الحفظ مباشرة بقيمة محلية مختلفة في نموذج الاختبار.

**القبول:** لا تُحفظ 30/PASS الناتجة من حجم محلي 2000 مع بقاء الدليل 1000. يعيد الحفظ الحساب من المصدر المعتمد أو يرفض اختلاف المدخل. تتفق إعادة التحميل والمراجعة والتقرير على الحساب نفسه. تمر التصحيحات المشروعة عبر التسوية الموقعة فقط. هذا الاختبار لا يطلب تعديل snapshot تاريخي محمي.

### RT-02 — الدقة والحدود بعد الحفظ — F02

جهّز عدًّا 1 وحجمًا 800 لتر مع حد إجراء 1، وحد تنبيه 1 إذا سمحت سياسة بيانات الاختبار بذلك. تحقق من 1.25 قبل الحفظ، ثم افحص ResultCFU والحالة والتدقيق والتقرير. اختبر كذلك 1.00 و1.50 والقيم الواقعة مباشرة فوق الحد وتحته، مع سياسة التقريب المتفق عليها.

**القبول:** لا تنخفض النتيجة المخزنة إلى 1 بسبب تحويل إلى int، ولا يتحول تجاوز الإجراء إلى Pass/Alert بسبب اختلاف الدقة. إن كانت السياسة تعتمد التقريب قبل القرار، يجب توثيق ذلك وتطبيقه نفسه في جميع المسارات دون تناقض.

### RT-03 — نافذتا EM والصفوف غير المعدلة — F03

افتح حدثًا مسموح التحرير في نافذتين قبل إدخال النتائج. احفظ نتيجة لوحة A من الأولى. أدخل لوحة B فقط من الثانية، بينما A ما تزال فارغة في نسختها القديمة. أعد الاختبار بوجود قيم قديمة غير فارغة وبإضافة/إزالة لوحة عبر مسار مسموح.

**القبول:** ترفض النسخة القديمة الحفظ برسالة تعارض، أو تدمج تعديلات مستقلة وفق عقد صريح يحفظ المجموعة الموثوقة. لا تمحو A، ولا يُشتق FinalResult من مجموعة قديمة، ولا يبقى أثر جزئي بعد رفض العملية.

### RT-04 — ذرية القيم السابقة للتدقيق — F03

أوقف عملية A في نافذة الاختبار بعد تحميل القيم السابقة وقبل الكتابة. احفظ تغييرًا من B، ثم تابع A. افحص القيمة السابقة الفعلية للتحديث وما سُجل في التدقيق. كرر الاختبار بفشل متعمد قبل التوقيع أو قبل إدراج التدقيق.

**القبول:** إما يرفض تعارض A بالكامل، أو يصف التدقيق بدقة deleted/inserted للعملية المقبولة. لا توجد نتائج بلا توقيع/تدقيق، ولا سجلات نجاح منفصلة عن عملية مرتجعة.

### RT-05 — المياه وتعديل الملاحظات فقط — F04

افتح نتيجة 5 في نافذتين. احفظ 10 من الأولى. عدل الملاحظات فقط من الثانية ثم احفظ. كرر التجربة مع صف مطلوب غير معدل محليًا تغيّر على الاتصال الآخر.

**القبول:** لا تُعاد النتيجة إلى 5. يُرفض التعارض أو تحفظ الملاحظة وحدها دون تبديل قيمة النتيجة أو دليلها وتوقيعها وتوقيتها. تتطابق الحالة الإجمالية مع جميع النتائج المطلوبة الموثوقة.

### RT-06 — استهلاك صيغة المواصفة كاملًا — F05

شغّل حالات F05 الأربع في probes، ثم أضف صيغ الوحدات والمسافات والفواصل والسياق المعتمدة بالموقع. اختبر NMT وNLT والحدود الصارمة والمساواة والنطاق والعوامل العلمية، وعبارات غير مدعومة وOR.

**القبول:** لا يتحول `NLT 1 * 10^3` إلى شرط `>=1`، ولا يُحذف شرط قبول غير معروف لإعطاء Conforms. لا يعاد تفسير الفاصل `=` كشرط إضافي في `NMT = 100` أو `RANGE = 95-105`. لا تُخلط حدود TAMC بحدود TYMC أو درجات الحضانة.

### RT-07 — التعارض بين المصدر النصي والحد المنظم — F06

شغّل حالتي `STRICT_STRUCTURED_CONFLICT` و`MULTIPLE_UPPER_STRUCTURED_CONFLICT`. أضف حالات مساواة حقيقية، وحدودًا متكررة، وحدًا صارمًا يختلف في شمول المساواة، ومصدرًا منظمًا غير قابل للتحليل.

**القبول:** يُرفض التعارض أو يوجّه إلى Check Required. لا يكفي عدّ معاملات <= لاكتشاف التعارض. لا يعتمد الإصدار أو المراجعة على تفسير أقدم من المصدر الحالي المطلوب التحقق منه.

### RT-08 — القفل وتغيير بيانات الاعتماد أثناء المصادقة — F07

استخدم حاجز اختبار بعد قراءة المستخدم والتحقق من كلمة المرور وقبل إتمام تحديث النجاح. من اتصال إداري مستقل، اقفل الحساب ثم أكمل A. كرر التجربة مع تغيير كلمة المرور، ومع مسار ترقية التجزئة، ومع التوقيع الإلكتروني.

**القبول:** لا يُمسح القفل الأحدث، ولا تُنشأ جلسة/إمضاء من بيانات اعتماد متقادمة، ولا تستبدل ترقية التجزئة كلمة مرور أحدث. يجوز للنظام طلب تحقق جديد عند التعارض، لكن لا يجوز تجاوزه بصمت. لا تُسجل كلمات المرور في سجلات الاختبار.

### RT-09 — سحب صلاحية إدخال EM أثناء التوقيع — F08

ابدأ حفظ EM بمستخدم يملك CanEnterResults. أثناء فتح نافذة التوقيع، اسحب تلك الصلاحية مع إبقاء الحساب نشطًا. أكمل التوقيع الصحيح.

**القبول:** يرفض فحص المعاملة الحفظ، وتبقى بيانات النتائج وحالة الحدث والتوقيع والتدقيق بلا تغيير ناجح جزئي. سجّل الدور الفعلي لحظة المعاملة، لا قيمة مخبأة في الواجهة.

### RT-10 — الحدود التاريخية والتسويات في الاتجاهات — F09

جهز لوحة بحدود أصلية، ولوحة تاريخية بلا حدود أصلية لها تسوية موقعة صالحة، ولوحة بلا أي دليل مكتمل. اختبر كذلك تسوية لاحقة تحل صراحة محل السابقة.

**القبول:** تستخدم الشاشة والفحص المسبق والاتجاهات الدليل الفعال نفسه، وتظهر هوية مصدره. تبقى حالة غياب الدليل غير مقيمة/محجوبة وفق العقد، ولا تُستبدل بحدود اليوم.

## اختبارات عدم التراجع والقبول الأشمل

### RT-11 — حماية PRM للمجموعة الكاملة

اختبر تعديل صف غير محفوظ محليًا، وإضافة/حذف صف مطلوب، وتغيير التوقيت أو المتطلبات أو حالة العينة من نافذة ثانية، قبل الحفظ والتقديم والمراجعة والاعتماد.

**القبول:** يُكتشف تغير المجموعة ودليلها، وتُرفض الحالة القديمة دون أثر جزئي. لا يسمح إصلاح المحلّل أو الأداء بتجاوز الحماية القائمة، ولا يغيّر تعديل الملاحظات حقول دليل النتيجة.

### RT-12 — قفل الفحص المسبق والترحيلات

ابدأ فحصًا شاملًا ممسكًا بالقفل المشترك، وحاول بدء الترحيل الحصري. اعكس الترتيب ثم اختبر الاستثناء والإلغاء وإغلاق الاتصال.

**القبول:** لا تتداخل قراءة الفحص الشامل مع تغيير المخطط. يعود النظام برسالة تحكم واضحة عند عدم الحصول على القفل وفق سياسة الانتظار، وتُحرر الأقفال بعد انتهاء جميع المسارات.

### RT-13 — الترحيل على قاعدة جديدة وقاعدة قديمة

طبّق baseline والترحيلات المعتمدة بالترتيب على قاعدة معزولة، ثم اختبر إعادة التشغيل والنسخة القديمة المعروفة وعطلًا متعمدًا وسط ترحيل مناسب. تحقق من سجل الإصدارات ومنع انجراف البصمات ومن مسارات التشغيل دون إذن DDL.

**القبول:** لا تُعلن نسخة مكتملة قبل اكتمال التغيير، ولا يُترك مخطط جزئي صامت. لا تُعدل بصمات البيان لإخفاء تغيير غير مضبوط. يجب اختبار خطة النسخ الاحتياطي والاستعادة خارج قاعدة التكامل المؤقتة.

### RT-14 — التوقيت وفصل الأدوار وجودة الدليل

اختبر إكمال حضانة مبكرًا أو بدليل ناقص، ومحاولة المراجع مراجعة عمله، وحفظ/اعتماد نتائج OOS دون استيفاء حالة التحقيق المطلوبة. يشمل ذلك PRM والمياه وEM والأوساط الزرعية بحسب مساراتها.

**القبول:** تُمنع التحولات غير المسموحة من خدمة الكتابة نفسها، لا من الأزرار فقط، وتبقى بيانات التوقيت والتوقيع والتدقيق ذرية. اختبر ترتيب اعتماد آخر تحرير خلية قبل التحقق من مبرر OOS في WPF؛ هذا اختبار حدود واجهة وليس عيبًا مؤكدًا ضمن الملاحظات التسع.

### RT-15 — الشهادات وإعادة الطباعة

أصدر شهادة معتمدة، ثم غيّر بيانات مرجعية لاحقة واختبر إعادة طباعتها وإعادة إصدارها وفق المسار المسموح. اختبر سباق إصدارين واللقطة المفقودة أو البصمة غير المتطابقة.

**القبول:** تحافظ إعادة الطباعة على الدليل الأصلي، ويمنع النظام الإصدار عند غياب الدليل أو تضاربه. افحص بصريًا شعار الموقع والجداول الطويلة وترقيم الصفحات واللغة وعدم قص التوقيعات.

### RT-16 — الاستيراد الخارجي

اختبر CSV/XLSX بحجم وحدود صفوف مسموحة ومرفوضة، وخلايا صيغة بلا قيم مخبأة، ومصدر مكرر، ومراجعة واعتماد بواسطة نفس المستورد، وتغير حالة دفعة أثناء المراجعة.

**القبول:** تُحفظ بصمة المصدر ودليل المراجعة وتُرفض الحالات غير المسموحة. لا تُنفذ الصيغ أو الروابط الخارجية، وتُعرض حدود البيانات والثقة في تفسيرها. لا تعدّل بيانات المصدر الأصلي لتسهيل قبول الاختبار.

### RT-17 — الواجهة وإعداد الموقع

اختبر العربية والإنجليزية ودقة شاشة مختلفة والتنقل وإعادة التحميل وإلغاء التوقيع وانقطاع الاتصال أثناء الحفظ. تحقق من إعداد اتصال الموقع ووضع التشغيل وسياسة شهادة TLS والحسابات المسموحة.

**القبول:** لا توحي الواجهة بنجاح عملية مرتجعة، ولا تحجب أخطاء التعارض، ولا تُعرض تفاصيل اتصال حساسة للمستخدم العادي. لا يستخدم نشر Production تجاوزات Development. سجّل الزمن الفعلي لحفظ عدد لوحات واقعي بدل افتراض أداء من الفحص النصي.

## سجل الإغلاق المطلوب

لكل حالة سجّل نسخة المصدر وقاعدة الاختبار والمتطلبات السابقة وخطوات الإعادة والنتيجة المتوقعة والفعلية وكود الخروج والأدلة المرتبطة وهوية منفذ الاختبار ومراجع الإغلاق. سجّل الاختبار غير المنفذ صراحة، ولا تعتبر غياب إخفاق مسجل دليل نجاح.
