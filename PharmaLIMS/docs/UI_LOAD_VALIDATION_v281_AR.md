# PharmaLIMS 2026.9.16.281 — UI / Load Validation Protocol

هذا البروتوكول يغلق فجوة **غياب دليل الأداء التشغيلي** كشرط Release Gate. لا تدّعي الحزمة أن الأداء تم إثباته داخل المراجعة المصدرية.

## بيئة الاختبار
- Windows workstation ممثل للإنتاج.
- نفس .NET 8 Desktop runtime/publish mode المخطط له.
- SQL Server ممثل للإنتاج من حيث latency/CPU/storage.
- نسخة بيانات غير إنتاجية وبحجم ممثل أو أكبر.
- لا تستخدم بيانات مرضى/أشخاص حقيقية في الاختبار.

## السيناريوهات
1. Sample Management: تحميل/فلترة/فتح قائمة كبيرة ممثلة لحجم الموقع.
2. Results Entry: فتح عينة متعددة الاختبارات، إدخال/حفظ/إعادة تحميل، ومحاولة تعديل متزامن من جلستين.
3. EM Results: حدث بعدد لوحات ممثل لأعلى حجم متوقع، حساب/حفظ/مراجعة.
4. PRM: عينة كاملة متعددة المواصفات مع مراجعة/اعتماد.
5. Reports/Trends: نطاق تاريخي كبير، توليد التقرير، التصدير والطباعة.
6. User Management: فتح القائمة وتعديل مستخدم مع جلسة ثانية لتأكيد optimistic concurrency.

## القياسات المطلوبة
سجل لكل سيناريو: حجم البيانات، عدد المستخدمين المتزامنين، زمن الاستجابة الملاحظ، CPU/Memory للعميل، SQL waits/timeouts، وأي UI freeze أو خطأ.
يجب أن تكون حدود القبول أرقامًا معتمدة من الموقع/QA وليست افتراضات من الكود.

## معايير سلامة غير قابلة للتفاوض
- لا unhandled exception.
- لا data loss أو stale overwrite.
- لا bypass للصلاحيات أو التوقيع.
- لا timeout غير معالج.
- لا تعليق واجهة يمنع المستخدم من معرفة حالة الحفظ.
- أي فشل يفتح deviation/defect ويمنع اعتماد Release حتى إعادة الاختبار.

## الدليل
أرفق screenshots/logs ونسخة من Release Acceptance Checklist المولدة من System Preflight وموقعة/مراجعة حسب SOP الموقع.
