# إصلاح UAT بتاريخ 2026-10-31

## السبب
في v309 كانت إعادة المصادقة الخاصة بـ Review/Approve تقرأ اعتماد المستخدم من قاعدة Activity المنفصلة، بينما Login وChange Password وإدارة الحسابات تستخدم قاعدة EQ001 الرئيسية. هذا جعل `qa` قادرًا على تسجيل الدخول للتطبيق لكنه يُرفض عند Approve بسبب حالة credential مكررة/قديمة في Activity DB.

## الإصلاح
- كلمة مرور وهوية الموقّع تُتحقق الآن من قاعدة EQ001 الرئيسية عبر Trusted Windows Host.
- قاعدة Activity تبقى مسؤولة عن ActivityID/status/rowversion، الصلاحية المحلية Review/Approve، فصل الواجبات، والسجل الموقّع.
- لا يتم نسخ password hash أو salt بين القاعدتين.
- إذا كان `PasswordChangedAt` فارغًا في الحساب الرئيسي، يفرض التطبيق Change Password قبل فتح workspace.
- ترحيل ActivitySigning الجديد: `20261031_001_Activity_Signing_Primary_Identity_Authority.sql`.

## النشر على بيئة UAT الحالية
أغلق كل نوافذ PharmaLIMS، افتح PowerShell كمسؤول من مجلد المصدر المصحح، ثم شغّل:

```powershell
.\scripts\Deploy-V309ActivityIdentityHotfix.ps1
```

السكربت يرفض أي بيئة غير UAT، يتحقق من اتصال Primary/ActivitySigning ومن SHA-256 للترحيل، يبني Host والعميل، يطبق `20261031_001` ويسجله في ledger داخل Transaction، يأخذ Backup للـruntime، ثم ينشر ويعيد تشغيل الخدمة. إذا فشل نسخ binaries يحاول إرجاع الـruntime من النسخة الاحتياطية.

بعد PASS:
1. افتح العميل تحت Windows account المربوط بـ `qa`.
2. إذا طلب Change Password، أكمله أولًا.
3. افتح Activity 10 وهي `Reviewed` ونفّذ `Approve` مرة واحدة بحساب `qa`.
4. تحقق من signature/status في قاعدة ActivitySigning قبل أي قبول UAT.

لا تعِد Review للنشاط 10، ولا تعدل `CredentialInitialized` أو password hashes يدويًا.
